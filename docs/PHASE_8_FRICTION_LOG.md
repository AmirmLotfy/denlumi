# Phase 8 fictional task friction log

This is agent-run local QA on fictional records, not observed customer or independent human usability research. No real animal interaction was performed.

| Task | Observed friction | Change and verification |
| --- | --- | --- |
| Open Today and session history in the browser | Authenticated GETs without an `Origin` header returned `INVALID_ORIGIN`. | Read routes now accept an absent Origin while still checking host, session and household scope; write routes retain same-origin checks. Production-browser suite passed 18/18. |
| Save a session observation in the new review journey | The write succeeded, but a following history GET failed; the UI called the entire step “refused.” | Fixed the GET guard and split the UI result into write failure versus saved-but-refresh-failed. Full SC06 browser journey now reaches confirmed pause and private preview. |
| Use a one-pet session report | Before selecting the observed pet, the target menu offered that same lone pet, although the server would reject self-direction. | One-pet target menu now has only “No target or unknown.” SC01 and SC02 browser tests pass and assert no second option. |
| Run broad browser coverage | The runtime demo-entry guard stopped the thirteenth fictional account creation within one minute. | Additional shape tests now seed isolated local test households and set authenticated cookies; the ordinary sample-entry tests still exercise the real picker. Runtime guard remains in place; combined production-browser suite passed 18/18. |
| Save a fictional routine report in Today | The first UI attempt saved the report, then the automatic current-state reread unmounted the form and erased its local success notice. | The saved result notice now belongs to the persistent Today view. The routine browser test passed with a visible report state, conflicting caregiver report and foreign-household refusal. |
| Run all Phase 8/9 browser specs together | An earlier spec closed the shared Playwright worker database pool before the new routine test seeded its fixture. | Removed per-file pool shutdowns; the final combined production-browser run passed 20/20. |
| Type a report while the fictional caregiver loads | The main household screen could appear before caregiver loading finished; that final entry step cleared text already entered in the report form. | Reset entry fields before awaiting the caregiver read. A delayed real caregiver response test preserves the typed fictional marker; the final combined production-browser run passed 21/21. |
| Refresh a reviewed handover while planning reads fail | A simulated planning GET 503 displayed an error but left the old exact-handover control on screen. | Current-state read failure now clears review, handover, draft and preflight controls while preserving local Stop; a successful fresh read restores the handover. Focused outage test and affected 16/16 production-browser run passed. This was a simulated HTTP failure, not a real database outage. |
| Ask for a fresh current-plan answer while the assistant endpoint fails | A simulated assistant HTTP 503 showed an error but left the previous answer visible, which could be mistaken for the new result. | A new turn clears the earlier answer before making the request. The failed turn shows an error and keeps Stop available; a recovered turn produces a fresh authenticated MCP answer. The post-fix full browser selection passed 26/26. |
| Lose the app's database connection during a current-plan check-in | In an isolated drill, a task-owned production app was pointed at a nonexistent local Postgres database while the browser retained its earlier answer. | The endpoint returned 503, the older answer disappeared, and local Stop stayed visible. Restarting the task-owned app with the valid database returned a fresh answer. The shared Supabase service was untouched; this does not prove hosted failover. |

Still unobserved with a human participant: comprehension of reported versus verified state, Stop/pending-sync status, plan review and handover meaning, multi-pet dependencies, private export, and non-audio recovery. A future session should use fictional tasks and record participant role, task outcome, confusion and revision without inventing customer evidence.
